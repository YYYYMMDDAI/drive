# SplitEase 仕様書テンプレート（HIG + OOUI反映 / 簡易版）

> このドキュメントは「コードを書く前の前提仕様書」です（構造定義のみ）。
> 
> **Web検索メモ**: 本環境から外部サイトへのHTTPアクセスが `403 Forbidden` となり、一次情報ページを直接取得できませんでした。したがって以下のHIG/OOUI要点は、一般的に広く参照される原則（Clarity/Deference/Depth、オブジェクト中心設計など）を基に整理しています。

---

## 1. プロジェクト目的

### 解決したい具体的課題
- iPhoneで「動画を見ながら調べる/メモする」を1アプリ内で完結したい。
- iOSのネイティブ同時分割制約を回避しつつ、2-3タップで開始できる体験を提供したい。

### 対象ユーザー
- 日本在住 iPhone ユーザー（20-40代）
- 通勤・学習・在宅ワークで「ながら見」を多用する層

### 価値仮説（他と何が違うか）
- 単純なWebビューアではなく、**目的別プリセット**（動画+SNS / 動画+メモ / 検索+辞書）を即時起動できる。
- ローカル完結（履歴・設定保存）で、プライバシー不安を低減する。

## 3. 技術選択の前提条件

### 処理場所
- 現段階: 端末内（ブラウザ内 state / localStorage）中心
- 次段階: iOSネイティブ化時は Core Data / AppStorage 優先

### 想定データサイズ・負荷
- 軽量テキスト（メモ、プリセット情報）中心
- 同時表示する2ペインは外部コンテンツ埋め込みでメモリ負荷増を想定

### OS・ブラウザ制約
- iOS Safari / WKWebView でのメモリ・自動再生・埋め込み制限に注意
- 外部サイトの `X-Frame-Options` / `CSP` により表示不可ケースあり

### 外部API / SDK 使用可否
- MVPでは必須外部APIなし
- 将来: StoreKit / App Intents / App Store Connect API を導入

## 4. 設計原理（必須参照ドキュメント）

### UI設計: Apple HIG（要点）
- **Clarity**: 情報階層を明確化（メインタスク=ペア選択と分割調整）
- **Deference**: UIは控えめに、コンテンツを主役にする
- **Depth**: 状態遷移を自然に（プリセット選択→即デュアル表示）
- 一貫したナビゲーションと、主要アクションの視認性を最優先

### UI設計: OOUI（オブジェクト定義）
- ユーザーの「タスク」ではなく、**操作対象オブジェクト**を先に定義
- 例: Preset / Pane / Note / SubscriptionStatus
- 画面は「オブジェクトの状態確認・編集」の場として構成

### UX方針
- **オブジェクト指向**を採用
  - 理由: SplitEaseは「ペア（Preset）」が中心資産で、再利用・編集・保存の文脈が明確

### アクセシビリティ要件
- Dynamic Type: テキスト拡大時でも操作不能領域を作らない
- コントラスト: WCAG AA相当（少なくとも本文 4.5:1）
- VoiceOver: ペイン/ハンドル/主要ボタンにアクセシビリティラベルを付与

## 5. ドメインモデル定義

### Core Object
1. **UserPreference**
   - 状態: theme, lastPresetId, splitRatio
   - 責務: 表示設定の保持

2. **Preset**
   - 状態: id, name, description, topContent, bottomContent, isPremiumOnly
   - 責務: デュアル表示の組み合わせ定義

3. **PaneSession**
   - 状態: topSource, bottomSource, startedAt, splitRatio
   - 責務: 現在の表示セッション管理

4. **Note**
   - 状態: text, updatedAt, presetId
   - 責務: メモデータ保持

5. **SubscriptionStatus**
   - 状態: isPremium, planType, expiresAt
   - 責務: 機能制限判定（無料3件など）

## 6. 画面構成と遷移

### 画面一覧（責務ベース）
- **Home / Dual View**: 2ペイン表示と比率調整
- **Preset Picker**: Preset一覧選択
- **Upgrade Modal**: Premiumへの導線
- **Settings**: テーマ・既定設定・制限説明

### ナビゲーション構造
- 起点: Home
- Home から Preset Picker / Settings / Upgrade へ遷移
- Preset 選択後は Home に戻って即反映

### 統合・分離の判断基準
- 起動3タップ以内を優先し、Home に主要操作を集約
- 高頻度操作は統合、低頻度設定は Settings に分離

## 7. 非機能要件

### パフォーマンス基準
- 初回表示体感: 1秒台前半目標（MVP）
- UI応答遅延: 100ms台を目標

### オフライン対応
- 設定・メモ・プリセット情報はローカル保持
- 外部コンテンツ自体はオンライン依存

### セキュリティ・プライバシー
- 収集データ最小化（原則ゼロ）
- 個人情報をサーバー送信しない設計を優先

### ログ・エラーハンドリング
- ユーザー表示: 「原因+対処」の簡潔メッセージ
- 開発向け: 失敗箇所を特定できる構造化ログ
